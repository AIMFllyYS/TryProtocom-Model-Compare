## 怎么运行 / 怎么验证

```bash
# 启动（评测用 bench.json 里的 start 命令，cwd 在哪一层都能跑）
PORT=8080 DB_PATH=/var/lib/blob-http/db.json node server.js

# 自测（不自己起服务，只打已在运行的实例）
BASE_URL=http://127.0.0.1:8080 node test/run-tests.js
```

我实际做的验证（本地 Node 24，行为与评测机 Node 22 一致）：

1. **`test/run-tests.js`：42 项断言全部通过**（退出码 0）。覆盖 CRUD、`ETag` 与 `Last-Modified` 语义、
   条件请求的四种状态码与求值顺序、`Range` 的 9 种形态（合法 / 越界 / `-0` / 空对象 / 非法 / 多段 / 弱 ETag / `If-Range`）、
   列表分页与 `next_after`、5 MiB 边界、413 不影响旧版本、并发原子性、错误格式与「永不 500」。
2. **`test/fuzz.js`：196 次畸形/恶意请求，0 个问题**——没有 5xx、没有堆栈泄露、连接不断，服务仍然健康。
3. **重启持久化**：用同一个 `DB_PATH` 杀掉进程再拉起，对象内容、`ETag`、`Last-Modified` 完全不变（`test/manual-persistence.js`）。
4. **真实下载工具**：`curl -o f -r 0-9` 取前半段，再 `curl -C -` 续传，拼接结果与完整文件逐字节一致，
   服务端返回 `206` + `Content-Range: bytes 10-19/20`。
5. **裸 socket 核对原始响应字节**：`304` 无响应体但带 `ETag`/`Last-Modified`；`416` 带 `Content-Range: bytes */20`；
   `412` 是标准错误 JSON。
6. **按 bench.json 的命令端到端跑通**：`setup` 为空 → `start` 起服务 → `health` 返回 200 → `test` 命令 42/42 通过；
   `start` / `test` 在**工作目录**与 **`blob-http/` 目录**两种 cwd 下都验证过。
7. **变异测试（验证自测脚本能否识破“故意改错的实现”）**：我把实现改坏三次并确认自测脚本**失败并返回退出码 1**：
   - 让 `If-None-Match` 永远不命中 → 304 用例失败；
   - 让 `ETag` 掺入名字 → “相同内容必须同 ETag” 用例失败（**第一次没抓住**，据此把该用例加强成“名字字符不同 / 名字长度不同 / 不同时间重传”三种比较后才抓住）；
   - 把 `If-Match`/`If-None-Match` 的判定挪出写锁 → 两条并发原子性用例同时失败。
   三次改动都已逐字节还原（SHA256 与基线一致）。

## 几个值得你重点看的设计点

- **落盘时序**（`lib/store.js`）：内容写临时文件 → `fsync` → `rename` → `fsync` 目录 → 元数据同样一遍，
  **全部完成后才发响应**。删除时顺序相反（先提交元数据再删内容），崩溃最多留孤儿文件，不会留下坏对象；
  启动时自愈：内容文件缺失的条目直接丢弃。
- **原子性**（`server.js` 的 `handlePut`）：条件判断与写入在同一把写锁内，收完 body 后**再复检一次**当前状态。
  8 个并发 `If-None-Match: *` 只成功 1 个、其余 7 个 `412`；`If-Match` 同理。读路径完全不加锁。
- **大对象不爆内存**：上传边收边写临时文件并增量算 sha256（不在内存缓冲整个对象），下载用
  `createReadStream().pipe(res)`，`Range` 直接指定 `start/end`，任意偏移都不需要读前导字节。
- **一个容易踩的坑**：URL 库会把 `/api/blobs/..` 规范化成 `/api`，导致“`.`/`..` 是非法名字”这条校验根本触发不了
  （会变成 404 而不是 400）。所以路由用**原始请求行分段 + 逐段解码**，而不是 `new URL().pathname`；
  自测里对应地用**裸 socket** 发这种请求（`fetch` 会在客户端就把它折叠掉）。
- **413 的连接处理**：超限时**先把请求体读完再回 413**，避免客户端只看到 `ECONNRESET` 而读不到状态码。

## 已知限制

- 单进程、单磁盘目录的小型对象存储：没有分片、索引、鉴权、多租户、配额、GC；元数据全量放在一个 JSON 文件里，
  对象数量极大时启动会变慢。
- 所有写操作串行化在一把锁内（这是原子语义的代价）；读互不阻塞。
- 只支持单段 `Range`（按规格），多段范围按“忽略 Range”处理，返回完整内容。
- `ETag` 只由内容决定（按规格“内容相同则相同”），所以同内容但 `Content-Type` 不同的覆盖会 **ETag 不变、Last-Modified 变化**，
  这是规格两条约束叠加的必然结果，已在 `DECISIONS.md` 第 4/5 条写明。
- 没有设置 `Cache-Control` 等缓存策略响应头（规格未要求，避免影响 CDN/浏览器默认行为）。

细节与取舍理由都写在 `blob-http/DECISIONS.md`，用法与接口在 `blob-http/README.md`。
