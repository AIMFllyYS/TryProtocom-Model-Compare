## 怎么运行 / 怎么验证

```bash
cd parking-quote
PORT=8080 BENCH_MODE=1 node src/server.js          # 终端 A
BASE_URL=http://127.0.0.1:8080 node test/quote.test.js   # 终端 B
```

实际做过的验证（都是真跑出来的）：

1. **全量测试**：对着运行中的实例跑，`75 tests / 75 pass / 0 fail`，退出码 0。`BENCH_MODE=1` 与不设置两种形态各跑一遍，均全绿（reset 端点分别是 204 与 404）。
2. **变异测试**：把 15 处常见实现错误注入代码（夜间起点 21:00、封顶 5000、时区改 UTC、分钟数向下取整、车型折扣截断、去掉宽限期、忽略遗失票据、TOO_LONG 边界差一、优惠券不推进计费起点、405 变 404、404 变 200 等），逐一确认测试失败 —— **15/15 全部被捕获**。这个工具在交付目录里，改完代码可以随时复跑。
3. **真实浏览器**：用 Chromium 打开一个页面，跨源 `fetch` 打本服务，`GET /health → 200`、`POST /api/quote → 200 {"minutes":90,…,"amount_cents":900}`、`POST` 坏 body → `400 VALIDATION_ERROR` 均正确送达并渲染；服务端的 stderr 访问日志同时记录到 404 / 405 / 422 三种响应确实发出。
4. **手工核对**：规格里给的示例单据（09:00→10:30 = 900 分）逐字一致；另外抽查了跨自然日、车型折扣、遗失票据、优惠券、恰好 7 天（10080 分钟 / 7 天各封顶 4000 / 合计 28000）等单据。
5. **路由行为**：未知路径 404、路径存在方法不对 405（带 `Allow` 头）、`BENCH_MODE` 关闭时 reset 端点 404、恶意输入不返回 500、错误体不泄露堆栈。

## 几个我自己拍板的地方（都写进了 DECISIONS.md）

- **首段永远是 60 分钟窗口**：只停 30 分钟也按首段计费（夜间 300 分，不是 150）。`150` 只可能来自第二个及以后的 30 分钟单元。
- **`capped` 用严格大于**：当日合计正好 4000 时 `capped=false`（封顶没有实际截断任何东西）。
- **`days[].cents` 是折扣前的单日费用**（已按夜间价与封顶处理），车型折扣和遗失票据只体现在 `amount_cents`；遗失票据多出的 5000 − 停车费不摊到任何一天。
- **可选字段传 `null` 算类型错误**（400），"缺省"用省略字段表达。
- **`TOO_LONG` 用向上取整后的分钟数判定**：7 天减 1 秒 = 10080 分钟 → 允许；7 天加 1 秒 → 10081 → 拒绝。
- **不注册规格外的路由**（没有 UI、没有 `/`），避免和"路径不存在 → 404"打架；文档与示例都放在 README。

## 已知限制

- **浏览器页面跨源调用**：普通 `OPTIONS` 探测按规格返回 405；只有浏览器真正的 CORS 预检（带 `Access-Control-Request-Method` 头）才返回 204 放行。这是为了不破坏 405 契约又能让闸机前端直接调用。
- **时间戳格式**：接受 `YYYY-MM-DD` + `T`/`空格` + `HH:mm[:ss[.小数]]` + `Z`/`±hh:mm`；拒绝无偏移、`±hhmm`（无冒号）、2 月 30 日这类非法日期。秒可选是因为 ISO-8601 允许降精度，题目只强调"必须带时区偏移"。
- **无 Web UI**：本题交付的是 API 服务，前端不在范围内。
- 开发环境是 Windows + Node 24，评测目标是 Linux + Node 22；用到的 API（`node:http`、`fetch`、`node:test`）在 Node 22 均可用，但**未在 Linux 上实跑过**——这是唯一未亲自验证的环境差异。
- 服务监听 Node 默认未指定地址（Linux 上为双栈 `::`），`127.0.0.1` 与 `localhost` 都能访问；`PORT` 非法时回落 8080 并在 stderr 提示。
