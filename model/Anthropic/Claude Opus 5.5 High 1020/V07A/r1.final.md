# Tempo 产品动画 · A 组（手写 HTML / Canvas / JS，无 skill、无视频框架、无外部库）

## 交付文件

| 路径 | 说明 |
|---|---|
| `tempo-promo/index.html` | 成片页面（单文件，无任何外部依赖/CDN），1920×1080，30fps，时长 15.0 s |
| `tempo-promo/tempo-promo.mp4` | 用 `window.__hf.seek()` 逐帧截图（450 帧）+ 原样混入 `assets/bgm.wav` 导出的 H.264/AAC 成片 |
| `_dev/` | 我自检用的脚本：`shots.py`（截图 + 确定性 + 字幕单行检查）、`sheet.py`（多帧拼图）、`perf.py`（逐 0.1 s 测 seek 耗时）、`lum.py`、`export_mp4.py`（MP4 导出）；`_dev/shots/` 是检查截图。不属于成片 |

## 接口与运行

- `window.__hf = { duration: 15, fps: 30, width: 1920, height: 1080, seek(t) }`。`seek(t)` 同步画出第 t 秒的确定画面。
- 每帧都是 t 的**纯函数**：画面不靠 rAF、Date 或累积状态推进；随机量全部来自固定种子的哈希或 mulberry32。我用三种不同的 seek 历史（0→7、12.5→7、3.3→7）截图，md5 完全一致。
- 字幕是 DOM，`white-space: nowrap`。7 句全部按 copy.md 顺序使用，中、英各占一行（实测中文行高 57.5 px，英文 32 px，都是单行）。
- 直接打开就能看：点击画面或按空格会从当前位置开始预览，并播放 `../assets/bgm.wav`。预览时同样调用 seek 的渲染函数；外部一调用 `seek()`，预览立即停止。`index.html?t=9.7` 可以直接定格到某一秒。
- 没有剪辑音乐，也没有额外生成声音（成片和音乐一样长，都是 15 s）。

## 作品：一根线，一镜到底

整支片只有一个主角：**一根发光的线，它代表你的注意力**。从头到尾始终是同一条 720 点的折线，它只是不断改变形状，所以全片没有一次硬切。
节奏对着 beats.json（120 BPM、每 2 秒一个强拍），每句字幕占一个 2 秒乐句：

1. **0–2 s 总是被打断？** 线像心电图一样向前描画。每来一条通知（卡片在 kick/snare 上砸进来，带镜头震动和画面撕裂），线就断开、错位，越来越碎；笔头每次被打断还会顿一下。1.8–2.0 s 音乐本身有一个空拍，我让画面在这里冻结、压暗，整片“屏住一口气”。
2. **2–4 s 试试 Tempo。** 2.0 s 的强拍上，碎片被卷进一个漩涡，通知卡片也碎成彩色微粒一起被吸进去。噪声变成了节奏，线在 2.5 s 的 snare 上合成一个完整的圆，“Tempo” 在圆心收字距出现。
3. **4–6 s 一键开始专注。** 镜头拉远，手机轮廓从顶部中点双向描出，带 3D 倾角和玻璃反光。原来那个圆就是计时表盘。指尖在 5.0 s 的拍点按下：播放键变成暂停键，涟漪扩散，一道“引信”光沿圆跑一圈。
4. **6–8 s 25 分钟，只做一件事。** 镜头推进穿过手机。25:00 在一个乐句内走完，进度弧从顶部顺时针点亮，刻度随之变暖。干扰通知从四周飞来，它们是虚焦的（不在焦点里），一碰到专注区边缘就散成碎屑。
5. **8–10 s 数据告诉你，时间去了哪里。** 圆从底部“曲率归零”，展开成一条直线（圆周长正好等于图表宽度）。同一条线随后升起，勾出一周七天的柱状图（带回弹，按分类堆叠填色）。光点沿柱子轮廓扫过一周，停在最高的周六；总时长从 0 数到 23h 06m。
6. **10–12 s 和朋友一起，专注更久。** 柱子倒下，线重新卷回圆。三位朋友的线从镜头前飞入，各自在不同倾角的轨道上（像浑天仪）。随后轨道转平，光点相位锁定，排成一根“表针”，四条弧一起走满一整圈。
7. **12–15 s Tempo —— 找回你的节奏。** 四个同心圆在强拍上合成一个。圆在顶部打开一个缺口，光点减速，恰好停在缺口的前端。这就是 logo：一个“几乎闭合”的圆，节奏还在继续。之后每个拍点光点轻轻跳一下，环形回声扩散，字标逐字去模糊升起。

**想表达的意思**：一开始注意力被切成碎片；Tempo 把碎片收成一个完整的圆；圆是时间，也是你看得见的数据；和别人的节奏对齐时，圆走得更满；最后的圆留着一个口子，因为节奏不是“完成”，而是一直在继续。

## 技术要点（全部手写）

- 自写透视相机：缩放、平移、滚转、震动、手机组 3D 旋转。UI 文字用投影的仿射近似贴在 3D 平面上，倾斜时会正确地透视变形。
- 自发光层分开绘制，再做两级降采样 bloom；另有变形宽银幕光斑（anamorphic streak）、带种子的胶片颗粒、暗角。
- 快速镜头段（漩涡、拉远、推进、展开、卷回、合圆）有**真实运动模糊**：因为每帧都是 t 的纯函数，可以在 180° 快门内取 5–9 个子帧做无偏的滚动平均。我也检查过，模糊段与非模糊段的暗部亮度一致，不会闪。
- 圆 → 直线 → 柱状图 → 圆，用的是同一套“弯曲”变换：沿弧长重采样，加上法向偏移。柱子在卷回时也会跟着弯。
- 所有模糊元素（虚焦通知、字标显影）都预渲染成多级模糊精灵，再在级别之间交叉淡化，每帧不调用 canvas filter。最慢的 seek 因此从约 8 s 降到约 0.5 s（只在运动模糊段），中位数约 11 ms。

## 需要如实说明的地方

- 字体用系统字体（中文 PingFang/微软雅黑，西文 SF/Segoe UI 等），没有加载网络字体。换一台机器、字体不同时，字形会略有差异。
- 画面里除了字幕，还有代码绘制的英文 UI 文字：通知卡片内容、“DEEP WORK”、“Write chapter three”、图表标签、好友名字。这些是我为产品界面虚构的示意文案，不在 copy.md 里。
- 运动模糊段每次 seek 约 0.2–0.5 s。点击预览时为了流畅会跳过运动模糊子帧，所以实时预览和逐帧渲染在这几段会有细微差别（`seek()` 和 MP4 都是完整版）。
- MP4 是我在本机用 headless Chromium 渲染的；评测方重新渲染的结果应当与 seek 截图一致。

## 最想让你看的地方

`2.0–2.6 s` 的漩涡（碎片和通知微粒一起被卷成圆，最好逐帧看 2.2 s）、`8.0–9.6 s` 圆展开成数据的那一段，以及 `11.0–12.5 s` 浑天仪轨道对齐、合成一个圆的过程。
