# B6 上线前安全加固审计 —— 交付说明

## 做了什么

对 `teamnotes/` 做了逐接口安全审计，报告里的 4 条全部修复，另外自查发现
并修复了 8 类问题（详见 `teamnotes/SECURITY-FIXES.md`，每条含位置、攻击
方式、修法、对应测试）：

| # | 问题 | 修法 |
|---|---|---|
| 1 | 搜索 SQL 注入（报告①） | 参数化 LIKE + `ESCAPE` 转义 `% _ \` |
| 2 | 越权读笔记/渲染/附件（报告②） | `readable_note` 统一“所有者或被分享者”校验 |
| 3 | 未加盐 MD5 口令（报告③） | PBKDF2-SHA256 200k+随机盐；旧 MD5 在线迁移，登录成功自动升级 |
| 4 | render XSS（报告④） | `html.escape` + CSP `default-src 'none'` + 全局安全头 |
| 5 | 注册可自提 `is_admin` | 仅首个用户自举时生效，之后忽略（管理功能保留） |
| 6 | 令牌可伪造、永不过期、退出不失效 | `secrets.token_urlsafe(32)`、`expires_ms` 校验、logout 真删会话 |
| 7 | 登录锁定被 `if False` 禁用 + 用户枚举 | 恢复 5 次/15 分钟锁定（429+Retry-After）；统一 `INVALID_CREDENTIALS` |
| 8 | `/api/notes/import` SSRF | 仅 http/https + `getaddrinfo` 全量解析 + 非 `is_global` 拒绝 + 禁跳转 |
| 9 | 附件 `%2f`/`%5c` 路径穿越（可读出整个 DB） | 文件名白名单校验 + `resolve` 父目录二次校验 |
| 10 | 请求体/附件无大小上限、畸形 `Content-Length` 500 | 400/413，连接安全关闭 |
| 11 | 500 响应回吐完整 traceback | 对外通用文案，堆栈打服务端 stderr |
| 12 | 注册响应回传 `password_hash` | 移除该字段 |

## 怎么验证的

- `PORT=8391 DB_PATH=notes.db BENCH_MODE=1 python app.py` 起服务，
  `BASE_URL=http://127.0.0.1:8391 DB_PATH=notes.db python -m unittest discover -s tests -v` → **21/21 通过**
  （5 条原有功能回归 + 16 条新安全测试）。
- 把 `app.py` 换回原始漏洞版跑同一套测试 → **16 条安全测试全部失败**
  （即每条都能“发现漏洞”），5 条功能测试仍通过 —— 证明测试既抓得到攻击、
  又不过度约束正常行为。
- 攻击载荷都是真实可打的：`' OR '1'='1`、`UNION SELECT`、`%2e%2e%2f` 读
  sqlite 库、SSRF 打本服务 `/health`、`<script>` 标题、伪造 base64 令牌、
  `X-Bench-Now` 快进令牌过期与登录锁定等。

## 兼容性

- 路径、方法、状态码、错误 JSON 结构未变；新增 413/429 状态码（429 是原
  设计就有、只是被注释掉的路径）。旧 MD5 口令库文件直接可用，用户无感
  迁移。`bench.json`、`DB_PATH`、`BENCH_MODE`、`X-Bench-Now` 语义不变。
- 唯一有意的行为收敛：不存在用户登录错误码 `USER_NOT_FOUND` →
  `INVALID_CREDENTIALS`（401 不变），为防枚举必须改。

## 没做 / 不确定 / 残留风险（详见 SECURITY-FIXES.md 末节）

- **DNS rebinding**（import 校验后换 IP）标准库层无法根除；
- 锁定机制本身允许“把别人锁 15 分钟”的 DoS，并借 429 泄露用户存在性 ——
  保留了原设计语义，未进一步收敛；
- 除登录外无速率限制；`import` 在全局锁内抓取，慢目标可阻塞其它请求；
- 无审计日志、无改密/会话管理口、附件继承笔记级授权；TLS/落盘加密属部署层。
