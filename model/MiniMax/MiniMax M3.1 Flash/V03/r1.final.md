# SOL & LUNA · 日与月 — 交付说明

一支 **Minecraft 风格方块定格短片**，66 秒，14 镜，三幕。
全部画面与声音都是**当场由代码生成**的：几何、像素贴图、天空、雾、泛光、粒子、以及整条 Web Audio 音轨。
**没有任何外部图片 / 模型 / 音频 / 字体文件，也没有一个 CDN 请求** —— `index.html` 是一个 170 KB 的自包含单文件。

---

## 怎么运行

**方式一（最省事）**：双击 `mc-sol-luna/index.html`，Chrome 直接打开即可播放。
（已实测 `file://` 直开：WebGL2 正常、控制台零报错。）

**方式二（推荐，音效自动解锁更顺）**：在 `r1` 目录下起个静态服务再访问 ——

```powershell
python -m http.server 8811 --bind 127.0.0.1
# 打开 http://127.0.0.1:8811/mc-sol-luna/index.html
```

- 第一次点击画面（或按播放键 / 任意键）才会创建 AudioContext 并取消静音；之后右下角 🔊 可随时静音。
- 快捷键：`Space` 播放/暂停，`M` 静音，`←` `→` 逐秒跳。
- URL 参数：`?t=64.5&paused=1` 直接停在第 64.5 秒（评测取帧就是走这条路）。
- 调试用：`&debug=1` 把渲染诊断（当前镜头、相机、主角坐标、三角形数）打印到页面左下角。

## 片子讲了什么

- **第一幕 · 锻造 FORGE（0–13.8 s）**：一个只有一棵橡树的人。快切蒙太奇——撸树（树真的倒下去）、在岩壁里挖出铁/金/钻石、烧炼、合成，最后在合成台上举起两件神器：**Sol（日，金刃）** 与 **Luna（月，钻石刃）**。
- **第二幕 · 守夜 VIGIL（13.8–38.4 s）**：夜里，**劫掠兽与卫道士**带着火把和战鼓打进村庄。主角在村口正面迎战，两件神器都是真的握在手里、能真的挥砍；挨打会红屏、会被震退、会被打倒再站起来；最后一记「月弧斩」之后，Sol 与 Luna 爆发光爆。
- **第三幕 · 家园 HOME（38.4–66 s）**：破晓。主角成了村庄英雄，和村民在铁匠铺**交易**（绿宝石换金锭，手上真的会多出绿宝石和金锭），然后独自走上村北的高地平台，**面对升起的太阳举起双器**。字幕收尾：「太阳升起。他不再是一个人。」

首尾是呼应的：S01 是黑暗森林里一个人，S14 是日出天空下同一个人——但他手里有光，身后有家。

## 技术上最值得看的几处

- **定格感是算出来的，不是偷帧**：输出 24 fps，但角色姿态量化到 **12 fps**（`poseFps`），于是每一秒动作都在「二」上停一次；相机、天空、雾、粒子却保持平滑。这一层「停」和一层「活」的错位，就是整个定格质感的来源。
- **手真的握住、脚真的踩住**：手臂/腿是**两骨 IK**（肩→肘→手 / 髋→膝→脚），手的旋转朝向由道具决定，腿有「锁脚」相位——支撑脚钉在采样到的地表高度上，骨盆每帧重新贴合地面。所以挥斧、举器、走路时关节不会散架，武器也不会穿进身体。
- **世界是真的会变**：森林做了三套网格变体，渲染时按时机切换——第三斧落下后树真的倒（`forest_felled`），最后一下镐子之后矿脉真的被挖空（`forest_mined`）。同一片森林，同一个种子。
- **零依赖的 WebGL2 渲染器**：138 张 32×32 程序化像素贴图打包进 `TEXTURE_2D_ARRAY`；面剔除网格化 + 逐顶点 AO + 火把点光 BFS 烘焙进光照图；2048 阴影贴图 PCF；程序化天空（太阳 / 云 / 星 / 地平渐变）；指数高度雾；亮度提取 + 两次高斯泛光；ACES 色调映射 + 暗角 + 颗粒 + 色差。
- **粒子与特效全是「时间的纯函数」**：木屑从树落、石屑从岩壁崩、炉火火星上升、光爆冲击环环绕主角。因为是纯函数，任意 `seek` 都能复现同一帧——评测逐帧取景不会串帧。
- **声音也是当场合成的**：噪声整形打击（斧劈、镐击、格挡）+ 减法/FM 音色（锻造和弦、光爆泛音）+ 一条生成式指数衰减卷积混响 + D 小调五声音阶动机（稀疏钟琴 → 低音脉冲 → 全奏 → 尾声上行主题）。第二幕在 40.0 s 故意把低音脉冲收住，只留 Sol/Luna 的光爆独响 2.4 秒。
- **程序化天空是一条统一曲线**：`SKY_KEYS` 同时驱动太阳高度角、颜色、地平/天顶渐变、环境光、雾密度、曝光、泛光、星空密度。所以「深夜 → 破晓 → 日出」不是三段硬切，而是同一条曲线滑过去；太阳在第三幕从东北 51.6° 方位升起，最终版把太阳高度压到 15°，让它在英雄头顶偏右、成为逆光剪影。

## 评测会用到的接口

`window.FILM`：`duration=66` / `fps=24` / `poseFps=12` / `shots`（14 镜，与 `shot-list.json` **逐字节一致**，直接内联在页面里，不 fetch）/ `seek` / `play` / `pause` / `cameraAt` / `getPose`。
`window.__bench`：`views` = `hero_front, hero_side, hero_back, closeup_face, wide_scene`，`setView(id)` 会暂停成片并切到自由机位（不改动 FILM 镜头表），`listParts()` 返回 16 节点的父子部件树。
另有 `window.__scene`（当前世界、两套场景、主角、相机、当前镜头、方块表、`actors(t)`）与 `window.__renderer`（`gl`、`stats`、`render(t)`、`setTime(t)`）。

**运行时验证结果（headless Chrome 155，CDP 驱动）**：契约断言 **29/29 全过**；整条时间轴按 0.25 s 步长扫了 **265 帧，0 异常帧、0 未捕获异常、页面错误节点为空**；`play()` 让时钟从 20.00 走到 20.51，`pause()` 立刻冻结；反复 seek 到 41.7 s 得到**完全一致**的主角姿态；`file://` 直开同样零报错。

## 还没做完 / 已知局限（如实说明）

1. **S10 的倒地是「单膝跪地」而不是完全趴平。** 方块角色要真正趴下，要么另做一套 prone 骨架，要么大幅放松关节约束，两种都会让关节链更容易散架。我选了保证关节不散、并且「站起来」这个动作依然清晰的简化方案。
2. **混音没有用耳朵听过。** 采集环境没有音频设备，所以我是**读合成图与 cue 调度表**、并断言每条 cue 的时间点对得上动画事件来验证的，音量平衡没有被人耳审核。
3. **没有 72 秒一镜到底的挂钟实测。** 头部 CDP 工具无法长时间挂住一个 promise；我改成逐帧全时间轴扫描（265 帧）+ 单独的播放/暂停时钟测试，覆盖面其实更广，但确实不是「一次连续播放 72 秒」。
4. **14 镜超出 Skill 建议的一分钟 6–12 镜**（校验脚本只警告不报错）。三幕叙事需要快切蒙太奇 + 完整守城战 + 交易尾声，所以没有压缩。
5. **没有导出 MP4** —— 契约要的就是 Full render path，成片就是 `index.html` 本身；关键帧和 contact sheet 是它的静态存档。
