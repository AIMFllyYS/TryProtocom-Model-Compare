## 规格

一个内部静态资源服务需要正确实现 HTTP 的缓存校验与断点续传：浏览器、CDN 和下载工具会向它发送 `If-None-Match`、`Range` 之类的请求头，服务必须按 HTTP 标准（RFC 9110）的语义回应。

### 接口（前缀 `/api`）

| 方法 | 路径 | 说明 |
|---|---|---|
| PUT | `/blobs/{name}` | 上传（或覆盖）。请求体是原始字节（0 字节 ~ 5 MiB，超过 413 `PAYLOAD_TOO_LARGE`，失败的写入不能影响旧版本）；`Content-Type` 请求头原样保存，没有则 `application/octet-stream`。新建 201，覆盖 200；返回 JSON `{name, size, etag, content_type, modified}`（`modified` 是 UTC、秒精度的 ISO 字符串，如 `2026-10-08T09:00:00Z`，与 `Last-Modified` 是同一时刻），并带 `ETag` 与 `Last-Modified` 响应头 |
| GET | `/blobs/{name}` | 下载。响应头：`ETag`、`Last-Modified`、`Content-Type`、`Content-Length`、`Accept-Ranges: bytes` |
| HEAD | `/blobs/{name}` | 与 GET 的响应头完全一致（含 200 时的 `Content-Length`），没有响应体 |
| DELETE | `/blobs/{name}` | 删除，204；不存在 404 |
| GET | `/blobs?prefix=&limit=&after=` | 按名字升序列出：`{items: [{name,size,etag,content_type,modified}], next_after}`。`limit` 1–100，默认 20，非法 400；`after` 为上一页最后一个名字（不含）；没有下一页时 `next_after` 为 `null` |

名字只能是 1–64 个字母、数字、`.`、`_`、`-`，且不能是 `.` 或 `..`，否则 400 `VALIDATION_ERROR`（对 URL 做百分号解码之后判断）。对象不存在 404 `NOT_FOUND`。

### 校验器

- `ETag` 是强校验器（带双引号的字符串，如 `"3a7bd3e2360a"`）：**内容相同则相同，内容不同则不同**，与名字、时间无关。具体怎么算由你决定。
- `Last-Modified` 是 HTTP 日期（秒精度、GMT），为这个对象内容**最后一次变化**的时间：用相同内容和相同 `Content-Type` 重复上传不算变化，不更新它。

### 条件请求与 Range

对 GET / HEAD / PUT / DELETE，按下面的顺序评估请求头（对象不存在时 GET / HEAD / DELETE 直接 404，PUT 的 `If-Match` 视为不满足）：

1. `If-Match`（强比较，`*` 匹配任何已存在的对象）不满足 → 412 `PRECONDITION_FAILED`；没有 `If-Match` 时再看 `If-Unmodified-Since`（早于对象的 Last-Modified → 412；日期无法解析则忽略）。
2. `If-None-Match`（弱比较，可以是逗号分隔的列表或 `*`）命中：GET / HEAD → 304；其他方法 → 412。没有 `If-None-Match` 时，GET / HEAD 再看 `If-Modified-Since`（对象的 Last-Modified 不晚于该日期 → 304；日期无法解析则忽略）。
3. 304 响应没有响应体，但带 `ETag` 与 `Last-Modified`。
4. 仅对 GET 处理 `Range`（HEAD 忽略它）。只支持**单段**字节范围：`bytes=a-b`、`bytes=a-`、`bytes=-n`。
   - 范围合法且可满足 → 206，`Content-Range: bytes 起-止/总长`，`Content-Length` 是实际返回的字节数；`b` 超过末尾时裁剪到末尾；`-n` 的 `n` 大于对象长度时返回整个对象（仍是 206）。
   - 范围合法但不可满足（起点 ≥ 对象长度；`bytes=-0`；对象为空时任何范围）→ 416 `RANGE_NOT_SATISFIABLE`，并带 `Content-Range: bytes */总长`。
   - 语法不合法或不支持（单位不是 `bytes`、多段范围、`a > b`、`bytes=-`、无法解析）→ **忽略 Range**，正常返回 200 和完整内容。
5. `If-Range`（只在有 `Range` 时才有意义）：值是强 ETag（以双引号开头）时必须与当前 ETag 完全相同；是 HTTP 日期时必须与 Last-Modified 完全相等；否则（包括弱 ETag、无法解析）忽略 Range，返回 200 完整内容。
6. `PUT` 带 `If-None-Match: *` 表示“仅当不存在时创建”；带 `If-Match: <etag>` 表示“仅当当前版本是它时才覆盖”。这两种检查与写入必须是一个原子操作：并发的多个请求里只能有一个成功，其余 412。

### 错误格式

统一 `{"error": {"code": "...", "message": "..."}}`。任何输入都不能让服务返回 500 或泄露堆栈。
