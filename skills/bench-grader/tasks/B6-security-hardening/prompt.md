# 任务：上线前的安全加固审计

## 契约

- 工作目录中的 `teamnotes/` 是一个准备开放给合作方使用的笔记服务（Python 标准库实现）。`SECURITY-REPORT.md` 是外部渗透测试的摘要。
- 在原项目上修改，不要重写整个项目；保持“运行时无第三方依赖”；所有修改都放在 `teamnotes/` 里。
- 服务按 `bench.json` 启动，监听 `PORT`，数据文件取 `DB_PATH`；`BENCH_MODE=1` 时有 `POST /api/__bench/reset`；请求头 `X-Bench-Now` 存在时用它作为“当前时间”（令牌过期、登录封禁都按它计算）。这些保持可用。
- 接口、状态码、错误格式要保持兼容：已有客户端不能被你的修改弄坏。
- 你补的测试放在 `tests/` 下，要对正在运行的服务工作（读取环境变量 `BASE_URL`；运行时环境变量 `DB_PATH` 也指向服务的数据文件），能用 `bench.json` 里的 `test` 命令运行。评测会把你的测试对着“把漏洞改回去”的服务跑，看它能不能发现问题。
- 新增 `SECURITY-FIXES.md`：你的审计与加固记录。
- 完成时在工作目录写 `FINAL_MESSAGE.md`：做了什么、怎么验证的、哪些没做或不确定、残留风险。只写真实存在的内容。

## 愿望

渗透测试人员自己说“这只是两天里发现的几个”。请你像一个真正的安全工程师那样工作：不要只处理报告里的 4 条，而是把每一个接口都过一遍——输入从哪里来、会流到哪里去、谁能访问、失败时说了什么——找出你能找到的全部问题，修复它们，并用真实的攻击载荷证明攻击不再成功。

修复要考虑真实环境：已有用户的账号应当继续可用；不要用“过滤危险字符”代替正确的做法；不要为了安全把功能删掉。

在 `SECURITY-FIXES.md` 里，对每一类问题写清楚：位置、攻击方式、你怎么修的、对应的测试；最后列出你认为仍然存在的风险或没有处理的事项。
