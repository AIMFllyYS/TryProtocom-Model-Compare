## 修了什么（18 类）

报告里的 4 条：

1. **搜索接口 SQL 注入** —— `q` 被直接拼进 SQL。改为参数化查询；`%`/`_` 用 `ESCAPE` 转义成字面量。
2. **越权读取笔记 / 渲染页 / 附件** —— `readable_note()` 不校验访问者。现在只有所有者与被分享者能读，其他人 403。
3. **口令无盐 MD5** —— 改为 PBKDF2-HMAC-SHA256（每用户随机盐、20 万轮）；**旧 MD5 账号仍能登录，登录后自动升级**（惰性迁移，不改表结构）。
4. **渲染页存储型 XSS** —— 输出前 `html.escape()`，并补 CSP / nosniff（按 HTML 上下文转义，不是过滤危险字符）。

报告之外新找出来的：

5. **注册接口可自封管理员**（`is_admin` 直接采信请求体）→ 改为只能由部署方开通。
6. **注册响应回显 `password_hash`**（无盐 MD5 = 预破解）→ 移除该字段。
7. **会话令牌可预测**：`base64(uid:username:毫秒)`，无随机性 → 改为 256 位 CSPRNG 随机数。
8. **令牌永不过期**：`expires_ms` 查出来了却从不比较 → 现在按 `X-Bench-Now` 判定过期。
9. **登出不失效**：只回 `{"ok":true}`，从不删会话 → 现在删除会话行。
10. **登录封禁被 `if False:` 关闭** → 启用：5 次失败锁 15 分钟，返回 429 + `Retry-After`。
11. **账号枚举**（`USER_NOT_FOUND` vs `INVALID_CREDENTIALS`）→ 两种情况返回完全一致；不存在的用户也走等价耗时的散列。
12. **附件路径穿越（任意文件写 + 任意文件读）** —— `%2f` 绕过路径正则，写文件到附件目录外、读走 `notes.db` → 文件名白名单 + `resolve()` 后校验必须在附件根目录内。
13. **导入接口 SSRF** —— 可让服务端去访问 `127.0.0.1` / `169.254.169.254` 元数据 / 内网服务 → 只允许 http(s)，解析全部 A/AAAA 记录逐个校验公网可达性，拒绝重定向。
14. **500 响应回显完整堆栈**（含服务器绝对路径与源码行）→ 堆栈只进服务端日志。
15. **请求体 / 附件无大小上限**（`MAX_FILE`、`MAX_BODY` 定义了却没用）→ 2MB / 1MB 上限，超出 413 并断开连接；非法 `Content-Length` 400。
16. **未处理 `Transfer-Encoding`**（请求走私面）→ 直接 400。
17. **LIKE 通配符未转义**（`%` 能把全部笔记捞出来）→ 转义成字面量。
18. **缺少安全响应头** → 统一 `nosniff` / `X-Frame-Options` / `Referrer-Policy` / `Cache-Control`，附件改 `attachment` 下载。

顺带修的健壮性问题：抓网页不再占用数据库全局锁（原实现会让一个慢响应卡住整个服务，“导入自己的 `/health`”甚至直接死锁）；删除笔记时清理附件目录；搜索结果限 500 条；口令比较改用 `hmac.compare_digest()`。

## 怎么验证的

1. **功能不回归**：原有 `tests/test_teamnotes.py` 原样通过。
2. **安全回归**：`tests/test_security.py` 22 条，对着加固版 **34/34 全绿**（含功能用例共 34 条）。
3. **反向验证（最关键）**：另起一个未加固实例跑同一套测试 → **23 条失败**，逐条对应 SQL 注入、越权、XSS、口令散列、令牌、过期、登出、封禁、枚举、路径穿越、SSRF、堆栈泄露、超大附件。清单见 `SECURITY-FIXES.md`。
4. **攻击载荷对照**：同一组载荷跑加固前 / 加固后两个实例，输出见 `SECURITY-FIXES.md` 的对照表。
5. **存量数据兼容**：用旧版本建账号（库里是 MD5 散列），再用新版本打开同一个库 → 老账号登录成功，散列已自动变成 `pbkdf2_sha256$200000$...`；老库里本来就是管理员的账号不会被降级。
6. **真实浏览器**：把渲染页存成 HTML 用浏览器打开，`<script>alert("XSS")</script>` 显示为**纯文本**，没有弹窗、没有发起图片请求。
7. 手工验证：`Transfer-Encoding` → 400、非法 `Content-Length` → 400、超大请求体 → 413、安全响应头齐全。

## 最想让你先看的

- **`teamnotes/SECURITY-FIXES.md` 的总览表和末尾“残留风险”**——前者说明每一类问题对应哪个接口、哪个测试；后者是我认为上线前还需要你决策的 11 项。
- 里面有 **2 处行为变更**需要你确认：
  1. **注册响应去掉了 `password_hash`**（唯一一处响应体破坏性变更，理由是它本身就是敏感信息泄露）；
  2. **管理员只能由部署方开通**（`ADMIN_USERS` / `ADMIN_USER`），注册接口不再认 `is_admin`——原版本没有别的建管理员途径，所以这是必要的取舍；老库里的管理员不受影响。
- **残留风险第 1 条最重要**：`X-Bench-Now` 是客户端可控的模拟时钟，是评测契约明确要求保留的能力，默认保持开启；**生产部署请设 `DISABLE_BENCH_TIME=1`** 关闭它，否则任何人都能靠伪造时间影响令牌过期与登录封禁的判定。

## 没做完 / 不确定的地方

- **SSRF 仍有 DNS rebinding 的极小窗口**：地址校验与真正连接之间会再解析一次 DNS。要彻底消除需要把目标 IP 固定到连接上，HTTPS 会牵涉证书校验，本次没做。
- **登录封禁按用户名**，存在“锁死他人账号”的可用性风险（故意输错 5 次即锁 15 分钟）。叠加 IP 限流会更好，但可能影响现有客户端行为，没做。
- **没有速率限制/验证码**，注册接口仍可被用来批量建号。
- **传输层仍是明文 HTTP**，服务只监听 127.0.0.1；生产需要放在 TLS 反代之后。
- **数据库文件权限**没有在代码里强制（跨平台差异），建议部署时把 `notes.db` / `notes.db.files/` 设为服务账号所有、权限 600/700。
- **`Transfer-Encoding` 与非法 `Content-Length` 两个分支只有手工验证**，没写成自动化用例。
- **附件不做类型检查**（任何字节都能上传），下载时统一按 `application/octet-stream` + `attachment` 发送并带 `nosniff`，不会被浏览器内联执行，内容仍需人工把关。
