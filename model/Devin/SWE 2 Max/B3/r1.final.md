# B3 · 带租约的作业队列 — 交付说明

## 交付了什么

`job-queue/` 下是一个零依赖的 Node.js 实现（`server.js` 单文件，仅标准库）：

- 全部契约接口：入队 / 租用 / ack / nack / 续租 / 查询 / stats / 死信列表 / requeue，
  以及 `BENCH_MODE=1` 下的 `POST /api/__bench/reset`。
- `PORT`、`DB_PATH`、`X-Bench-Now`、惰性过期、统一错误格式、队列名校验，均按规格实现。
- `bench.json`：`start: node server.js`（无 setup），`test: node tests/api.test.js`，`health: /health`。
- `tests/api.test.js`：对运行中实例的黑盒测试，读 `BASE_URL`，全部时序断言用
  `X-Bench-Now` 驱动，共 **241+ 条断言**（health、全部校验分支、排序规则、
  租约边界 `now == expires_at`、过期致死、指数退避数值、令牌三类 409、
  死信排序、requeue、10 并发租用抢占等）。
- `README.md`（启动/接口/配置）、`DECISIONS.md`（所有规格未明处的裁决与理由）。

## 关键设计

- **持久化**：每次变更在响应前完成 `tmp 文件 write+fsync → rename 原子覆盖 →
  目录 fsync`。实测：300 个并发入队进行中强杀进程，重启后 301 条作业完好、
  seq 一致；租约状态、令牌、`attempts` 全部恢复。
- **惰性过期**：存储只记事实字段；`delayed/ready/leased` 与“过期致死”都按请求
  `now` 纯推导，不回写——时间倒退也不会产生不一致视图。
- **并发安全**：变更逻辑在请求体读完后的同步区间内完成，事件循环天然串行；
  并发测试证明 N 个 worker 不会拿到同一作业，令牌互不相同。

## 验证方式

1. `BASE_URL=http://127.0.0.1:18080 node tests/api.test.js` —— 全绿（241/241）。
2. 手工 curl 冒烟：201/204/400/404/409 各分支、无偏移时间头、空 body。
3. `taskkill /F` 后同 `DB_PATH` 重启：租期未到时 `leased`、到点 `ready`、
   旧令牌 `LEASE_EXPIRED`，行为无缝衔接。
4. 重启后再次跑全量测试仍全绿。

## 已知限制

- 整库快照写放大 O(库大小)/次变更；评测量级无压力，规模化需换 WAL/KV。
- 无长轮询 lease；worker 轮询（规格要求惰性时间语义，阻塞等待无意义）。
- 以上取舍及令牌校验顺序、`error`/`requeue`/`extend` 边界处理见 `DECISIONS.md`。
