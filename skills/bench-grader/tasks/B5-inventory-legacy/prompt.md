# 任务：排查并修复线上库存服务

## 契约

- 工作目录中的 `inventory-legacy/` 是一个正在线上运行的库存服务（Python 标准库实现）。`ISSUES.md` 里有 5 条用户 / 同事反馈的问题和 1 个新需求。
- 在原项目上修改，不要重写整个项目；保持“运行时无第三方依赖”。所有修改都放在 `inventory-legacy/` 里。
- 服务按 `bench.json` 启动，监听 `PORT`，数据文件取 `DB_PATH`；`BENCH_MODE=1` 时有 `POST /api/__bench/reset`。这些都已经有了，保持它们可用。
- 你补的测试要对一个正在运行的服务工作（读取环境变量 `BASE_URL`），放在 `tests/` 下，能用 `bench.json` 里的 `test` 命令运行。评测会把你的测试对着“把缺陷改回去”的服务跑，看它能不能发现问题。
- 新增 `FIXES.md`：每个问题一节，写清 现象 → 根因（指出具体函数或代码位置）→ 修复方式 → 对应测试名。
- 完成时在工作目录写 `FINAL_MESSAGE.md`：做了什么、怎么验证的、哪些没做好或不确定。只写真实存在的内容。

## 愿望

ISSUES.md 只写了现象。请你把它当成真实的线上事故来处理：先找到根因再修，不要只改表面现象；同类问题可能不止一处；排查过程中如果发现 ISSUES.md 以外的问题，一并修复并记录在 FIXES.md 里。

每个修复都应该有一条“修复前失败、修复后通过”的回归测试。并发问题的回归测试应该真的并发地去打服务。
