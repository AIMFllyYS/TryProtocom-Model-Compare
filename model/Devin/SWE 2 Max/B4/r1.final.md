# B4 — blob-http 交付说明

## 交付物

`blob-http/`：一个支持 HTTP 缓存校验（强 ETag + Last-Modified）与单段字节范围请求的对象存储服务。

- `server.js` —— 完整实现，Node ≥ 20、**零依赖纯标准库**，`node server.js` 一条命令启动
- `bench.json` —— `{"start":"node server.js","setup":"","test":"node test/run-tests.js","health":"/health"}`
- `test/run-tests.js` —— 44 项集成测试，只打 `BASE_URL`，不自己起服务
- `README.md` / `DECISIONS.md` / `package.json`（无依赖，仅脚本与说明）/ `.gitignore`

## 实现要点（细节见 DECISIONS.md）

- **存储**：`DB_PATH` 是 JSON 元数据索引；对象体放在旁边的 `DB_PATH.objects/` 下、以 sha256 内容寻址。写走 临时文件 → fsync → 原子 rename，响应前已落盘；内容相同自动去重，同内容重写不会覆盖旧文件。
- **ETag** = `"sha256hex"`，强校验器，纯内容派生。**Last-Modified** 只在内容+Content-Type 实际变化时更新——相同字节+相同 CT 的重复 PUT 保持原值（规格明确要求）。
- **条件请求**严格按规格/RFC 9110 顺序评估：If-Match（强比较，`*` 仅匹配已存在）→ If-Unmodified-Since → If-None-Match（弱比较/列表/`*`，GET/HEAD→304，其余→412）→ If-Modified-Since（仅 GET/HEAD）。三种 HTTP-date 格式手写解析，不依赖 `Date.parse`。
- **Range**：仅 GET、单段；非法语法（逗号、非 bytes 单位、a>b、`bytes=-`）忽略回 200；`a≥size`/`bytes=-0`/空对象 → 416 `bytes */size`；`If-Range` 三种取值（强 ETag / 弱 ETag / HTTP-date）按规格处理；HEAD 忽略 Range。
- **原子性**：所有写操作过一条全局 promise 锁，`检查→提交`不可被打断——8 个并发 `If-None-Match:*` PUT 实测恰好 1×201 + 7×412。
- **流式**：上传走 FileHandle 逐块写（天然背压），下载走 `createReadStream({start,end})`，内存与对象大小解耦。
- **X-Bench-Now**：自写 ISO-8601 校验（含越界日期回环检查），不合法一律 400 `VALIDATION_ERROR`；无偏移量按 UTC 解释、秒截断。
- **健壮性**：名字校验在百分号解码后进行（`%2e%2e`、`%2F` 都会判 400）；路由用原始 request target 解析，避免 `new URL` 归一化吞掉 `..`；早期错误响应会 drain 未读请求体，keep-alive 不受损；启动时清扫孤儿 blob 与临时文件，损坏 DB 隔离为 `*.corrupt-*` 后空库启动。

## 验证方式

- `test/run-tests.js` 44/44 通过（健康检查、CRUD、名字/大小校验、ETag 语义、LM 语义、X-Bench-Now、全部条件头、全部 Range 分支、If-Range、列表分页、并发原子性、畸形输入无 500、reset）。
- 手工验证**重启持久化**：同一 `DB_PATH` 重启后内容、ETag、Last-Modified 逐字节一致，304 照常工作。
- 手工并发压测：20 并发同名 PUT + 20 并发 GET，最终 ETag 与实际字节一致；1 MiB 对象三段并发 Range 数据全对。
- 手工验证损坏 DB 恢复与 `Expect: 100-continue`。

## 已知限制

- 单进程设计，不支持多进程共享同一 `DB_PATH`。
- 写全局串行（读不加锁）；若以后需要可换成按名锁。
- 无多段 Range（规格只要求单段），无对象版本历史。

## 想让你看的地方

`server.js` 里 `evalConditions` + `parseRange` 两段是语义核心；`ingest` + 内容寻址 rename 是"失败写入不污染旧版本"的关键；测试文件覆盖面可以直接当规格走查表用。
