## 规格

一个地下停车场要把计费规则做成服务。下面是计费部门给的全部规则，请完整、准确地实现。

### 接口

`POST /api/quote`，请求体 JSON：

| 字段 | 类型 | 说明 |
|---|---|---|
| `entry` | string，必填 | 进场时间，ISO-8601，**必须带时区偏移**（`Z` 或 `±hh:mm`），可带小数秒 |
| `exit` | string，必填 | 出场时间，格式同上 |
| `vehicle` | string，可选 | `standard`（默认）/ `ev` / `disabled` |
| `coupon_minutes` | integer，可选 | 优惠券抵扣的分钟数，0–600，默认 0 |
| `lost_ticket` | boolean，可选 | 是否遗失票据，默认 false |

成功返回 200：

```json
{"minutes": 90, "billable_minutes": 90, "days": [{"date": "2026-10-08", "cents": 900, "capped": false}], "amount_cents": 900}
```

`days` 按日期升序，只列出产生了费用的自然日；`cents` 是该日（已按夜间价和日封顶处理）的费用，`capped` 表示该日触发了封顶。`amount_cents` 是最终金额（分，整数）。

### 计费规则

1. **停留时长** `minutes` = 出场与进场之间相差的秒数向上取整到分钟。出场早于进场：422 `INVALID_RANGE`。超过 7 天（10080 分钟）：422 `TOO_LONG`；恰好 7 天允许。
2. **宽限期**：`minutes` ≤ 15 免费，`billable_minutes` = 0，`days` 为空（遗失票据另算，见第 8 条）。宽限期按**优惠券抵扣之前**的停留时长判断。
3. **可计费时长** `billable_minutes` = 超过宽限期时 `max(0, minutes − coupon_minutes)`。可计费时长为 0 时没有任何计费单元。
4. **计费单元**：计费从“进场时间 + `coupon_minutes` 分钟”开始。首段覆盖前 60 分钟，价格 600 分；之后每个**开始的** 30 分钟为一个单元，每单元 300 分。（可计费 61 分钟 = 首段 + 1 个单元；可计费 91 分钟 = 首段 + 2 个单元。）
5. **夜间价**：计费单元（包括首段）的**起始时刻**落在本地时间 22:00（含）到次日 06:00（不含）之间，该单元价格减半（600→300，300→150）。
6. **日封顶**：每个计费单元归属其起始时刻所在的**本地自然日**；每个自然日的费用合计最高 4000 分。
7. **车型**：对各日费用之和（封顶之后）按车型调整：`ev` 为 85%，`disabled` 为 50%，`standard` 不变。结果按“四舍五入到分，.5 向上进位”取整。
8. **遗失票据**：`lost_ticket` 为 true 时，`amount_cents = max(第 7 条的结果, 5000)`，即使停留在宽限期内也是如此。
9. **时区**：本地时间固定为 Asia/Shanghai（UTC+8，无夏令时）。入参带任何偏移量，都要先换算成这个时区再判断夜间和自然日。

### 错误格式

所有错误统一返回 `{"error": {"code": "...", "message": "..."}}`：

| HTTP | code | 场景 |
|---|---|---|
| 400 | `VALIDATION_ERROR` | 请求体不是合法 JSON 对象、字段缺失、类型或格式不对、`vehicle` 取值不合法、`coupon_minutes` 不是 0–600 的整数（布尔值、小数、字符串都不算）、`lost_ticket` 不是布尔值、时间没有时区偏移 |
| 404 | `NOT_FOUND` | 路径不存在 |
| 405 | `METHOD_NOT_ALLOWED` | 路径存在但方法不对 |
| 422 | `INVALID_RANGE` / `TOO_LONG` | 见第 1 条 |

输入校验（400）先于业务规则（422）。服务不能因为任何输入返回 500，也不能泄露堆栈。
