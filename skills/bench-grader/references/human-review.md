# 人工评分与 Agent 审查

## 何时询问用户
在全部运行完成自动评分、agent 项也已填写之后，**一次性**向用户发出评分请求。内容包括：
1. `review/index.html`（盲评页面，可直接打分并导出 CSV）或 `review/human_sheet.csv`；
2. `review/usage_needed.csv`（如有缺失的用时/费用）；
3. 一句话说明：共多少个人工项、多少个运行、大概需要多少分钟（按每项 20–40 秒估算）。

人工项 ≤ 8 个且会话有选择题提问工具时，可以直接逐项提问：题干 = 检查项描述 + 运行别名 + 作品路径，选项 = 4 个锚点。

## 盲评规范
- 只显示别名（R001…），别名按哈希打乱，与模型名的对应关系保存在 `review/aliases.json`，不要在询问中透露。
- 同一检查项的所有运行并排比较，先整体浏览一遍再打分。
- 动画题优先看统一渲染的评审视频（`_grading/timeline/review.mp4`），不要看模型自己导出的视频。
- 严格对照锚点；介于两档之间取低档；备注写出扣分原因，便于复核。
- 建议两位评审各评一次，分差 ≥ 2 的项讨论后定分（可选）。

## Agent 审查
- 只评 `method: agent` 的项。
- 每项必须在 `note` 写证据：文件路径 + 行号，或可复现的现象描述。
- 没有把握的项留空，交给用户。
- 不查看模型名；只按 `open` 列给出的路径阅读产出。
- 导入时加 `--by agent`；用户之后导入同一项会覆盖 agent 分数。

## 导入
```bash
python scripts/bench.py ingest-scores <csv> --by human|agent
```
CSV 至少包含 `item_id, alias, score`；score 为 0–3，可带小数；空值忽略。
