## 2. 契约实现核对

`window.__bench` 全部按契约实现（`aether9-site/src/50-main.js` 末尾），
另外按要求暴露了 `window.__scene` 与 `window.__renderer`。

| 契约项 | 实现 |
|---|---|
| `views` | `['overview','stage1_engines','stage2','gridfin_closeup','launch_pad']` |
| `setView(id)` | 切换到命名机位；相机立刻锁定（停止自动运镜），且镜头随箭体运动，不受飞行阶段影响 |
| `listParts()` | 返回 48 个部件的 `{ id, name, parent, object3dName }` 树 |
| `explodePart(id,on)` | 单部件（含子部件）沿径向拉出 / 复位 |
| `setExploded(on)` | 一键分级爆炸：一级与二级沿箭体轴线分离，发动机外扩，栅格舵与着陆腿展开，整流罩抬升 |
| `listHotspots()` | 7 个热点（整流罩 / 真空发动机 / 级间段 / 栅格舵 / 甲烷罐 / 液氧罐 / 推力框架） |
| `openHotspot(id)` | 打开说明并把镜头飞到该热点 |
| `launch()` | 复位到 T+0、自动进入 Flight 区块并开始计时 |
| `setTimeScale(k)` | 1–40 倍速（评测用的 20× 已验证可正常推进） |
| `getTelemetry()` | `{ t, altitudeKm, velocityMs, stage, phase, boosterAltitudeKm, … }`，分离后 `stage === 2` |
| `scrollToSection(id)` | 平滑滚动到 hero / specs / launch / reuse / cta |

**命名规范**（评测可直接核对）：

## 3. 页面结构与叙事

五个区块（首屏 / 参数 / 发射 / 复用 / 行动号召）共用**同一个 3D 世界**，没有分场景、没有切换加载：

- **首屏**：夜航灯光下的整箭、发射塔、推进剂储罐与火焰导流槽；相机缓慢环绕，标题在左侧、箭体偏右构图。
- **参数**：左侧参数表 + 右侧部件索引树；点表中任意一行，镜头会飞到制造这个数字的那块硬件上。
- **发射**：实时遥测条（MET / 高度 / 速度 / 级 / 阶段 / 推进剂 / 质量 / T/W），可拖动的时间轴带事件刻度，可暂停、变速、点击事件跳转。
- **复用**：回收循环（落台 → 检查 → 加注 → 复飞）+ 台账数字；滚动本区块即等于在时间轴上推进任务。
- **行动号召**：任务登记表（提交后给出回执）。

**转场是连续的一镜到底**：滚动即时间轴，推进器分离后相机自动切到正在返航的助推器，
助推器落台后镜头交给停在回收坪上的箭体，整流罩抛离、上面级点火、载荷分离、上面级再入落船，
全部在同一个空间里发生，没有黑场、没有重载。

## 4. 我额外做的交互

1. **可拆解的部件浏览器**——点 3D 里的任意零件、点部件树、点热点，都能打开同一块说明面板：
   这是什么、为什么这么设计、关键参数，并能单独把它从箭体上拉开。
2. **参数表 ↔ 硬件联动**——点一行参数，镜头直接飞到对应硬件。
3. **时间轴事件刻度**——点火、起飞、Max-Q、MECO、分离、二级点火、整流罩抛离、再入点火、着陆点火、
   触地、入轨、载荷分离、再入点火、落船，每一次点击都可跳转到那一刻。
4. **复用循环卡与台账**——四个节点可点，会同时改变场景时刻与台账数字（飞行次数 / 周转时间 / 单次节省 / 每公斤成本）。
5. **自由轨道**——拖拽旋转、滚轮缩放、复位机位；用户一动鼠标，自动运镜立刻让位。
6. **自适应画质**——检测到软件渲染器（SwiftShader / llvmpipe）时自动降级分辨率、关闭 MSAA 与阴影、砍掉一级辉光；
   有 GPU 时自动升到 2× DPR + 4× MSAA + 阴影。

### 新颖交互：**「推进剂燃尽剖切」**（Propellant Burn-Down Cutaway）

点开参数区块右侧的 **OPEN CUTAWAY**，箭体像工程剖面图一样被切开（裁剪面实时跟随相机，永远切掉靠近观众的一半，
外壳同时降为半透明幽灵），里面的液氧（青）与液甲烷（琥珀）两个液体体积露出来；
拖动 **SCRUB THE BURN** 滑杆，液面在四米直径的贮箱里真实下落，
右侧的质量预算实时重算：596.5 t → 262 t，T/W 3.03 → 4.21。

> **一句话**：它让用户亲眼看到「一级关机时还剩 4% 推进剂」是什么意思——那 4% 就是让 76 t 助推剂落回地面的
> 返场燃料，也正是「可复用」这件事的全部成本与全部意义。

## 5. 技术实现

**全部程序化，零外部资源**

- **几何**：`LatheGeometry` 生成真实的钟形喷管曲线；两级各 27 台发动机逐台建模（燃烧室、涡轮泵、再生冷却管、
  加强环、热防护盘）；栅格舵是 16 根梁搭出的真实格栅；着陆腿是套筒 + 屈曲芯；整流罩是旋转体半壳。
- **贴图**：机身蒙皮、碳纤维隔热层、粗糙度贴图、沙漠地面、着陆坪标识，全部用 Canvas2D 现场绘制
  （含面板缝、焊缝、检修口、跑道标线、程序化噪声）。
- **环境光照**：用代码搭一个微型「太空摄影棚」场景（渐变天幕 + 主光球 + 暖色补光 + 冷色轮廓光），
  经 `PMREMGenerator` 烘成环境贴图，负责金属反射；再叠加方向光 / 半球光 / 轮廓光 / 补光四灯位。
- **天空与星**：fbm 噪声的银河带 + 3000 颗带温度与闪烁的恒星（自定义着色器）。
- **特效**：自写后处理链——HalfFloat 场景缓冲 → 亮度提取 → 三级降采样高斯辉光 → 合成（ACES 色调映射 +
  色差 + 暗角 + 胶片颗粒），全部手写 GLSL，不依赖任何后期库。
- **火焰**：每个发动机一支程序化湍流羽流（3D 噪声 + 径向衰减 + 核心白热），引擎短舱受热会自发光。

**代码结构**（`src/`，构建时按序号拼接）

| 文件 | 职责 |
|---|---|
| `00-core.js` | 数学、程序化贴图工厂、材质库、PMREM 环境、自写后处理链 |
| `10-vehicle.js` | 箭体建模、部件注册表、热点、内部贮箱 |
| `20-world.js` | 天空、星、地面、发射塔与发射台、回收坪、无人回收船、灯光、三种灯光氛围 |
| `30-sim.js` | 任务时间线：上升曲线、推力方向程序、翻转、着陆、上面级再入落船、遥测、推进剂与质量模型 |
| `40-ui.js` | 镜头导演、滚动叙事、拾取、热点、检查器、剖切与质量预算、HUD |
| `50-main.js` | 启动、渲染循环、自适应画质、`window.__bench` |

**仿真模型**：一级上升速度按积分反推，保证 MECO 恰好落在 70.0 km / 2300 m/s；
T+160 s 分离后助推器继续滑行、翻转（T+165–186 s，绕垂直于航迹轴的轴转 180°）、
再入点火、两次着陆点火、T+500 s 触地；上面级 T+161.5 s 点火、T+520 s 入轨、T+640 s 载荷分离、
T+700 s 再入、T+904 s 落上无人回收船。遥测里的推进剂百分比、干重、T/W 与剖切视图里的液位来自同一套账本。

## 7. 已知边界（据实说明）

- 第二级返场段（再入落船）做了轨迹与姿态动画，但无人回收船是简化体量，没有甲板作业细节。
- 相机在快速任务推进时采用「硬跟随目标 + 缓动轨道偏移」的方式以免拖影，章节切换瞬间会有一次机位切换。
- 软渲染环境下帧率有限（为保证评测机可用，检测到软渲染会自动降分辨率与特效档位）；有 GPU 的机器上会自动升档。
- 没有音频。所有「音效位」都是视觉替代方案。
