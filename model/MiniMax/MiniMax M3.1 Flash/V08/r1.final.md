## 二、这片子讲的是什么

概念一句话：**天空从来都是一次性的，直到 Aether-9 把它变成可循环使用的东西。**

结构上影片本身就是那个"循环"：

1. **弃（0–6.45s）** — 太空里一具烧毁的、翻滚的、废弃的一级，旁白："过去，每一次升空，
   都留下一具空壳。" 到 T+4.55s，它自己转正、点火复活 —— 这是全片的转折点。
2. **回（6.20–9.40s）** — 甩镜切到夜间发射场，同一枚一级垂直落回着陆圆环。
3. **升（9.15–14.60s）** — 镜头从"完整的 118 m 箭体"推进到箭底，点火升空，
   左侧 118 m 尺寸标注线随箭体生长，右侧 4 片栅格舵清晰可读。
4. **分（14.35–18.70s）** — 穿过羽流冲上高空，地球蓝色边缘在下方，一级分离，
   右侧高度标尺的游标正好停在 70 km。
5. **载（18.50–22.60s）** — 二级点火入轨，120 t，整流罩张开，轨道椭圆自动描边。
6. **环（22.35–28.00s）** — 回收段再次降落，着陆圆环炸开、旋转、放大成第 5 幕那条
   轨道椭圆；地面溶解成太空；AETHER-9 / 复用天空 / REUSE THE SKY 字卡逐字装配完成。

**收尾的深意**：片尾那个圆，和 120 t 载荷绕行的那个椭圆，是同一个圆 —— 天空被复用。

片中每一个数字都出自 `assets/aether9-facts.md`，**没有编造任何参数**：
118 m / Ø 9 m / 21 台甲烷发动机 / 4 片栅格舵 / 二级 6 台（3 海平面 + 3 真空）/
T+160 s 分离 / 70 km 高度 / 120 t 完全复用 / 首飞 2027 Q2。
火箭几何按 118:9 ≈ 13.1:1 的真实比例在 SVG 里建出来（21 个发动机喷管逐个画出来）。

## 三、技术做法

- **全部画面是代码生成的**：没有用任何实拍或图库素材。
  - 火箭 / 助推器 / 二级 / 整流罩 = 参数化 SVG（`stage1SVG` / `stackSVG` / `stage2SVG`），
    按 118 m : 9 m 比例建网格，栅格舵带斜向格栅，21 只喷管按 5-6-5-5 排布。
  - 星空 = Canvas，用固定种子的 mulberry32 PRNG 画 900 颗星（可复现，无 `Math.random`），
    外加 34 颗 CSS/GSAP 呼吸的亮星。
  - 羽流 = 四层 SVG（外焰 / 中焰 / 焰心 / 马赫环）+ 径向辉光。
  - 发射台、探照灯塔、着陆圆环、地球边缘 = SVG / CSS 渐变。
  - 颗粒 = SVG feTurbulence 叠层。
- **确定性**：所有动画是一条 `gsap.timeline({paused:true})`，注册在 `window.__timelines["main"]`；
  随机量全部来自固定种子；无时钟依赖，逐帧 seek 渲染结果可复现。
- **字体**：Archivo Black（字标 / 数字）+ IBM Plex Mono（遥测 HUD）+ 思源黑体
  （`assets/fonts/NotoSansSC-*.otf`，现场用 fontTools 子集化到 113 KB，
  保证中文字形离线确定性渲染，不依赖系统字体）。
- **音频**：
  - 旁白用评测环境预装的 `bench_tts.py --voice zh-CN-YunxiNeural` 逐句生成 7 段 wav，
    放在 `voiceover` 音频组。
  - BGM 选 `bgm-a.wav`（21 s，比 bgm-b 密度更高、瞬态更连续，铺在旁白下更稳）。
    它由两段 clip 拼成 28 s（`bed-a` 0→21 s，`bed-b` 从源 0 s 重播 20.8→28 s，1.2 s 交叠）。
  - **用 HyperFrames 的 voiceover carve**：以 `voiceover` 组为源，对 BGM 做
    400 Hz–2.5 kHz 四段峰值滤波 + 动态闪避包络（强度 0.55，因为旁白较稀疏），
    旁白出现时音乐自动让位、句间自动回来。
  - SFX：tick（遥测提示）5 处、rumble（低频轰鸣）4 处、whoosh（转场掠过）2 处、
    impact（点火 / 触地）2 处，各自独立 track、独立增益。
  - 母线 `data-fx-chain` = `truepeak` 真峰值限幅（ceiling −1.5 dBTP）+ 一级总增益，
    这是 −1.4 dBTP 的来源。

## 四、怎么跑

```powershell
cd aether9-promo
npx --yes hyperframes@0.8.181 check     # 0 error；49/49 WCAG AA 文字对比度通过
npx --yes hyperframes@0.8.181 preview    # Studio 里可逐元素点改
npx --yes hyperframes@0.8.181 render --quality delivery --output final.mp4
```

项目里已带 `node_modules`（`@hyperframes/core`），因为 `scripts/carve.mjs` 需要它才能
重新生成 carve；换机器重跑 carve 时需要 `npm i -D @hyperframes/core`。

## 六、我做到的、没做到的、以及我希望你先看哪里

**希望你先看两处**：

1. **19.8–22.0s 的 120 T 与轨道椭圆** —— 数字用 Archivo Black 压到 150 px，
   轨道椭圆用 `stroke-dasharray` 自己描出来，和片尾是同一条椭圆。
2. **24.8–28.0s 落地 → 圆环炸开 → 字卡** —— 整片概念收在这里：着陆圆环放大成轨道，
   地面溶解成太空，"AETHER-9 / 复用天空 / REUSE THE SKY" 逐字落下。

**没做 / 留了余地的**：

- **转场没有用 registry 的 shader transition（whip-pan / light-leak 在 catalog 里是有的）**。
  原因：我的 6 个场景共用一条"连续镜头"逻辑（同一枚助推器、同一个着陆圆环），
  手写 GSAP 的速度匹配转场能精确控制这段连续性，而且避免 shader transition 会把工程
  切到 layered-composite 渲染路径、改变根节点填充行为（`hyperframes-core` 明确警告过）。
  代价是少了 shader 转场那点"物理感"。
- **组合是单文件 `index.html`（约 730 行）**。`hyperframes lint` 会因此报
  `composition_file_too_large` 和 6 条 `nested_structure_needs_subcomposition` 警告 ——
  官方推荐把 3 个以上硬切场景拆成 `compositions/*.html` 子组合，让 Studio 时间轴一行一个场景、
  便于逐场景编辑。我为了保证跨场景的连续性（羽流横扫、圆环morph、共享星空）选择了单文件。
  **lint 结果：0 error / 7 warning；check 结果：0 error / 0 warning / 7 info，49/49 文字对比度通过。**
- `npx hyperframes usage --json` 在本环境返回 `{"status":"unknown","reason":"unsupported_harness"}`，
  我没有猜测额度；`hyperframes skills update` 因 GitHub 不可达只做了"存在性校验"，
  所有 skill 都是按已安装版本阅读的。
- `bgm-b.wav` 没有使用（按契约"二选一"处理），仍原样保留在 assets 里。
- `assets/` 里我复制了预置素材（原文件未改名、未重新下载），`bgm-b.wav` 是
  `bgm-a.wav` 的副本，以保证项目目录自洽可独立渲染。

**事实边界**：片中只出现了事实表里有的参数。所有画面都是虚构火箭的代码化演绎，
没有任何真实航天影像。
