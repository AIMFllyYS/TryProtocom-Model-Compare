## 修了什么（按严重性）

**Critical**
1. 搜索接口 SQL 注入 → 可拖库（笔记、用户、会话）、可注入 `--` 按 ID 读别人的笔记；改为全参数化 + LIKE 通配符转义。
2. 越权（IDOR）：任何登录用户改笔记 ID 就能读正文、渲染页、下载附件；改为 owner 或被分享者才可见，越权统一 404（不暴露存在性）。
3. 口令无盐 MD5、注册接口回显哈希；改为 PBKDF2-HMAC-SHA256（26 万次 + 16 字节随机盐）常量时间比较，**旧 MD5 账号在下次成功登录时自动升级**（表结构不变，已用旧库实测）。
4. 注册接口客户端可传 `is_admin` 自授管理员；改为完全忽略该字段，管理员只能由部署方 `TEAMNOTES_ADMIN_USERS` 指定。
5. 附件名路径穿越：百分号编码的 `../` 可读任意文件（含 SQLite 库、源码），也可**写任意文件**；改为先解码再校验单层文件名 + 解析后校验父目录，拒绝分隔符/NUL/控制字符/盘符/Windows 设备名。
6. SSRF：`http://127.0.0.1`、内网、`file://` 都能抓取入库；改为仅 http/https、解析所有地址并要求公网地址（含 IPv6 NAT64/6to4/Teredo 特殊段）、禁重定向、1MB/3s 上限，并把网络抓取移出全局 DB 锁。

**High / Medium / Low**
7. 会话永不过期、登出不失效、令牌可预测（`base64(id:user:time)`）→ 随机令牌、过期校验、登出删除。
8. 登录封禁是 `if False` 死代码 → 5 次失败锁 15 分钟（429 + `Retry-After`），失败计数持久化，按 `X-Bench-Now` 计算。
9. 用户枚举（未知用户返回不同错误码）→ 统一 401 `INVALID_CREDENTIALS`，未知用户也做等时 PBKDF2 校验；未迁移的 MD5 账号失败路径额外补一次 PBKDF2，消除时序差异。
10. 请求体/上传无上限、非法 `Content-Length`/`Transfer-Encoding` → 2MB/1MB 上限 + 413，非法值 400，拒绝 TE 走私面。
11. 500 回显完整 traceback → 客户端只看到通用错误，细节写服务端 stderr。
12. 其余：LIKE 通配符语义、响应安全头（nosniff/XFO/Referrer-Policy/no-store/CSP）、HEAD/OPTIONS、协议级错误也走统一 JSON、隐藏 Python 版本、`/health` 无锁、超大 ID 404、删除笔记清理附件、畸形 JSON/请求目标映射为 4xx。

## 没做 / 不确定 / 残留风险（重要）

完整清单在 `SECURITY-FIXES.md §6`，这里只列最需要注意的：

1. **`X-Bench-Now` 是契约要求保留的“客户端可控时钟”**：能构造请求的人可以把时间推到未来以跳过登录封禁、或推到过去延长令牌有效期。因为题面明确要求“请求头存在时用它作为当前时间”，我保留了它；**生产部署必须移除或限制来源**。这是本次最大的残留风险，也是我在“契约 vs 真实安全”之间做的明确取舍。
2. **`BENCH_MODE=1` 的 `/api/__bench/reset` 无鉴权**（会清空全部数据），只允许测试环境开启。
3. **SSRF 的 DNS 重绑定 TOCTOU**：校验解析结果与实际连接是两次解析；生产建议域名 allowlist 或固定出口代理。已阻断字面量内网/回环/保留地址/非 http(s)/重定向。
4. **没有速率限制**：注册/登录/导入/上传都可被刷；PBKDF2 在全局锁内还会放大 CPU 型 DoS；账号锁定也可被用来锁死已知用户。建议反向代理限速。
5. **单进程 + 全局数据库锁**：并发吞吐有限（SSRF 已移出锁，但认证哈希仍在锁内）。生产建议多进程/WAL 或前置队列。
6. **没有审计日志**：登录失败、越权尝试、SSRF/穿越拒绝都不落盘；只有 5xx 写 stderr。建议加结构化审计日志并由网关保留访问日志。
7. **历史数据需一次性人工审计**：旧库中可能已有通过“注册自授管理员”漏洞提权的账号（上线前核对 `is_admin=1`）；长期不登录的旧 MD5 账号不会自动升级哈希，建议强制重置。
8. 部署层：默认明文 HTTP 且只绑 `127.0.0.1`，对外必须经 TLS 反向代理；SQLite/附件目录需磁盘与备份加密；附件不做病毒扫描/配额。
9. 未新增功能接口（为保持兼容）：没有“取消单条分享”“修改口令”“注销全部会话”“MFA”“登录设备管理”。
